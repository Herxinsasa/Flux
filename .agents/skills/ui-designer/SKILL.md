# UI Designer - UI 稿解析与界面契约

## 定位

`ui-designer` 把现成 UI 稿或已确认的界面需求转成可供详细设计、编码和审查使用的界面契约。

`docs/ui` 只保存 UI 稿件、标注、界面规则、交互状态和验收依据，不保存目标源码、组件/类拆分、状态管理、数据映射、通信实现或兼容技术方案。这些内容由 `design-writer` 写入同一份需求设计。

## 进入条件

- 需求规格已确认且阻塞问题为 0。
- 影响面状态为“已闭合”。
- 已识别受影响页面、窗口或组件区域。

任一条件不满足时停止，不以 UI 设计替代需求确认或影响面分析。

## 输入优先级

1. 用户提供的 Figma、Pencil、截图、标注稿、HTML 原型或设计说明。
2. 现有产品中的同类页面和组件模式。
3. 当前需求所需的最小视觉与交互澄清。

多数需求应直接解析现成 UI 稿。需求与 UI 稿冲突、稿件缺少关键状态或规则不明确时，列为阻塞问题并请用户确认，不自行取舍。

## 平台识别

识别 Web、Qt Widgets、Qt QML、混合或未知平台，是为了正确解释界面载体和交互语言，不是为了在本 Skill 中做前端架构设计。

- Web：页面、路由、弹窗、抽屉、表单、响应式和浏览器状态。
- Qt Widgets：窗口、对话框、Widget、`.ui`、控件状态和桌面尺寸。
- Qt QML：Page、Component、Dialog、Popup、property 和 signal 表达的交互。
- 混合：分别标明各自界面边界。

按平台读取 `references/web-frontend.md` 或 `references/qt-frontend.md`，只使用界面契约部分。

## 工作模式

### 已有 UI 稿

- 以稿件为准，不重新发明界面。
- 对齐需求项与稿件覆盖范围。
- 稿件中的需求外内容标为“非本次范围”。
- 默认态之外缺失的加载、空、错误、禁用、成功状态按需求必要性补查。

### 无 UI 稿但有现有模式

复用现有页面布局、控件、间距、文案和反馈模式，只描述本次新增或修改部分。常见于新增字段、列表列、提示、过滤条件和配置参数。

### 无 UI 稿且无现有模式

每轮只确认 1-2 个会影响编码的关键问题：界面位置、布局结构、交互结果、必要状态和视觉约束。不扩展为完整品牌或设计系统建设。

## 输出内容

写入：

```text
docs/ui/<需求迭代编号>-<需求主题>-ui.md
```

仅包含：

- UI 输入来源、版本和覆盖范围。
- 需求项与稿件对齐关系。
- 页面/窗口、入口、字段、布局、操作、状态、交互、校验和视觉约束。
- Web 响应式或 Qt 桌面尺寸、滚动、溢出等界面适配要求。
- UI 验收依据。
- 差异、缺口、阻塞问题和非本次范围。

明确禁止写入：

- 目标代码文件和函数。
- React/Vue 组件拆分或 Qt 类设计。
- 状态管理和缓存技术选型。
- UI 字段到接口/DTO 的代码映射。
- 通信、序列化、持久化和兼容实现策略。

## 流转规则

- 阻塞问题未归零：状态保持“待确认”，不得进入 `design-writer`。
- 界面契约已确认：`design-writer` 引用本文件，并补充前端/客户端技术设计和跨层数据契约。
- `dev-planner`、`dev-builder`、`code-review` 和 `code-tester` 使用本文件检查 UI 一致性，不从本文件获取技术实现方案。

## 自审查

```text
□ 是否优先解析现成 UI 稿？
□ 是否只描述本次需求涉及的界面和状态？
□ 需求外稿件内容是否进入非本次范围？
□ 是否没有写目标源码、类拆分、状态管理或通信实现？
□ 阻塞问题是否已确认后才流转？
```
