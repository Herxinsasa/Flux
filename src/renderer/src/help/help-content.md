# Flux 使用帮助

欢迎使用 Flux。这个页面覆盖最常用的工作流，帮助你在 3-5 分钟内上手。

## 1. 快速开始

1. 打开文件或文件夹。
2. 在右侧聊天区输入问题，或使用 @ 文件把上下文带给 Agent。
3. 需要特定能力时，使用 /Skill 显式调用，或在 Skill 管理页维护技能。
4. 选中文本可右键「引用」给 AI 分析，或「批注」留下评审意见。
5. 需要导出分析结果时，使用导出功能生成 Markdown 报告。

## 2. 主界面说明

### 左侧

- 文件树：浏览和选择工作区文件。
- 工作集/文件列表：每个已打开文件右侧有 `×`，可快速关闭该文件。
- 顶栏按钮：
  - 面板图标：显示/隐藏工作区。
  - 闪电：Skill 管理。
  - 批注图标：打开批注面板（带未解决批注数徽标）。
  - 机器人：显示/隐藏 AI 对话面板。
  - 太阳：主题切换。
  - 帮助：打开帮助中心。
- 批注面板与 AI 面板互斥：打开一个会自动收起另一个，面板宽度可拖拽调整。

- 顶部菜单：
  - 文件 / 编辑 / 段落 / 查看 / 帮助 这一排标准叫「菜单栏」，日常也可叫「功能栏」。
  - 编辑菜单支持剪切、复制、粘贴、查找和全选；在编辑器和文本输入框中都可使用。
  - 段落菜单可快速插入常用结构：一级标题、二级标题、水平分割线；适合快速整理文档层级。
  - 使用段落菜单插入内容时，会在当前光标位置写入，不会覆盖未选中的文本。
  - 若当前有选中文本，段落菜单会替换选中区域，便于快速重构章节内容。
  - 建议先插入标题再补正文，能更快形成清晰的大纲结构。
  - 帮助 > 使用说明：打开帮助中心。
  - 帮助 > 关于：查看应用图标、当前版本和项目主页链接。

### 中间

- 编辑器区：查看和编辑文件，Markdown、纯文本、日志各有专用视图。
- 专注模式（Ctrl+Shift+L）：隐藏侧栏与聊天/批注面板，只保留编辑器。

### 右侧

- AI 对话区：进行日志/代码分析。
- 支持工具调用流式反馈、进度提示和结果回显。

## 3. 编辑器使用

### Markdown 编辑器

- 工具栏「编辑 / 源码」切换所见即所得与源码视图；「大纲」在左侧显示 1-3 级标题目录，点击跳转。
- 工具栏缩放按钮与 Ctrl+= / Ctrl+- / Ctrl+0 等价，正文字号 12–24px。
- 未保存的文件名带 `*` 标记。

### 右键菜单

- **引用**：选中文本后把选区作为上下文发给 AI（未配置 AI 服务时该项禁用）。
- **批注**：选中文本后在原地写批注。
- **样式**：粗体 / 斜体 / 代码 / 引用 / 有序列表 / 无序列表 / 任务列表（需选中文本）。
- **段落**：插入一至五级标题。
- **插入**：链接 / 图片 / 表格 / 代码块 / 分割线。

### 表格编辑

- 光标置于表格内时，表格左上角浮出工具条：
  - 行列调整：弹出面板增减行/列数（最少 2 行 1 列）。
  - 左对齐 / 居中 / 右对齐：作用于当前列。
- 行列边缘还提供增删按钮与列宽拖拽手柄。

### 大日志查看（.log）

- 打开日志自动建立索引，顶部横幅显示「大日志索引视图 · 共 N 行」。
- 滚动时按需加载，支持千万行级日志流畅浏览；按 FATAL/ERROR/WARN/INFO/DEBUG 自动着色。
- 发送给 AI 时不会注入全文，只注入索引摘要（级别统计与错误样例行），AI 按需检索明细。

### 按扩展名选择视图

- `.md` / `.markdown` → Markdown 编辑器；`.log` → 大日志查看器；其它文件 → 纯文本编辑器。

## 4. 批注与评审

### 添加批注

- 在 Markdown 编辑模式选中文本 → 右键 →「批注」，写入内容后保存。
- 批注锚定的文本在编辑器内高亮；用户批注与 AI 批注样式不同。

### 管理批注

- 单击批注条目选中高亮，双击跳转到原文位置。
- 铅笔 / 垃圾桶按钮：编辑 / 删除（删除需确认）。
- 对勾按钮：在「未解决 / 已解决」间流转；面板顶部可筛选「未解决 / 全部」。
- 回复按钮：回复前先选择身份（修改人 / 评审人），回复按身份着色显示。

### 失效批注

- 原文被修改导致批注位置失效时，条目提示「位置已失效」。
- 先选中新文本，再点定位按钮即可用当前选区重新锚定。

### 批注存储与导出

- 批注保存在源文件同目录的 `<文件名>.review.json` 旁车文件中，跟随文件分发。
- 面板下载按钮可导出：Markdown 或 HTML；Markdown 可选脚注式或文末清单；范围可选全部或仅未解决。

## 5. Skill 使用

### 导入 Skill

- 支持导入单文件（.md）或目录（技能包）。
- 目录导入适合包含模板、脚本、附加说明的 Skill。

### 卸载 Skill

- 右上角删除按钮是软件内卸载，不会删除磁盘文件。
- 内置 Skill 不支持删除。

### 失效 Skill

- 当入口文件或资源目录缺失时，Skill 会显示已失效。
- 聊天发送前若命中失效 Skill，会给出明确提示并跳过注入。

## 6. AI 对话技巧

### @ 文件引用

- 输入 @ 弹出文件列表（工作区 + 已打开标签页），上下键选择、Enter 确认。
- 发送时会把文件内容拼接为上下文；超大文件只注入大小/行数元数据并提示。
- 用户消息下方显示上下文脚注（@文件、/技能、#行号），方便核对 AI 看到了什么。

### /Skill 显式调用

- 输入 / 可选择已安装 Skill。
- 适合强约束输出格式或固定分析流程。

### 引用编辑器选区

- 选中文本按 Alt+K，或右键「引用」，选区以 `@文件名#起始行-结束行` 形式进入输入框。
- 最多可挂 5 条引用，逐条可移除；超长选区自动截断并提示。

### 上下文管理

- 输入框上方实时显示历史消息、引用、正文的字符数与压缩摘要状态。
- 接近上限时提示；达上限自动压缩历史，仍超限则阻止发送。

### /compact 手动压缩

- 输入 `/compact [主题]` 发送，把当前会话压缩为摘要并持久化。

### 钉住结论

- AI 回复右上角钉住按钮：把结论钉入后续请求的 system 提示，长期生效。
- 输入框上方展示已钉条目；重复钉住会提示已存在或达上限。

### AI 写文件确认

- 工具 write_file 生成「确认 / 撤销」卡片，**确认前不落盘**，含 diff 行数统计。
- 应用时若目标文件有未保存修改会先提示确认；应用后编辑器即时更新并高亮变更行。

### 导出报告

- 检测到报告意图时，回复完成后出现「导出报告」按钮，默认文件名 `analysis-report.md`（问题总结为 `problem-summary.md`）。

### 其他技巧

- 输入框 ↑ / ↓ 回溯最近 5 条输入历史。
- 点击聊天消息中的 `file:line` 引用，自动跳转并高亮到目标行。
- Esc 取消正在运行的 Agent 任务。

## 7. 设置与连接

- 在设置中配置 Provider、模型、API Key。
- 供应商预设（Anthropic / OpenAI / DeepSeek / Kimi / GLM / Qwen 等）；自定义供应商需选协议类型（Anthropic Native / Anthropic Messages / OpenAI Chat Completions）。
- 默认模型旁刷新按钮：用 API Key 在线拉取模型列表（自定义供应商不支持），来源优先级为远程列表 > 已保存列表 > 内置目录。
- 建议先做「测试连接」，再保存。
- 连接失败时，界面显示通用错误，详细原因写入主进程日志。
- 高级设置中可「清空当前对话」：默认只保留本次运行内的 AI 对话，重启后不恢复历史。

## 9. 导出报告

- 分析完成后可导出 Markdown 报告。
- 推荐在导出前检查结论、风险和修复建议是否完整。

## 10. 常见问题

### Q1: 为什么我导入后看不到 Skill？

- 检查 frontmatter 是否包含 name。
- 检查是否与内置 Skill 重名。
- 重新打开 Skill 管理页刷新列表。

### Q2: 为什么某个 Skill 被标记为失效？

- Skill 的入口文件或资源目录不存在。
- 可在原路径恢复文件，或在 Skill 页卸载后重新导入。

### Q3: 为什么点击外部链接会跳浏览器？

- 这是安全与可用性设计，避免应用内弹窗阻塞主界面。

### Q4: 已打开文件太多，怎么快速整理？

- 在左侧工作集/文件列表中，点击文件行末 `×` 可逐个关闭。
- 建议只保留当前任务相关文件，减少切换成本。

### Q5: 为什么 AI 写文件没有直接生效？

- 出于安全考虑，write_file 结果以「确认/撤销」卡片展示，确认后才落盘。
- 如果你期望直接写入，请在需求中明确说明。

### Q6: 为什么大日志在聊天里只有摘要？

- 大日志不注入全文，只注入索引摘要（级别统计与样例行号），AI 按需检索明细，避免上下文溢出。

### Q7: 批注文件是什么，能删吗？

- `<文件名>.review.json` 是批注旁车文件，删除后该文件的批注全部丢失。
- 建议随文档一起归档，保证批注可追溯。

## 11. 建议工作流

1. 打开目标日志或代码文件。
2. 用 1-2 句描述你的目标和约束。
3. 必要时追加 @ 文件和 /Skill。
4. 先拿结论，再让 Agent 生成可执行修复步骤。
5. 对重要结论点「钉住」，让后续对话持续沿用。
6. 导出报告并归档到项目文档。

## 12. 反馈与迭代

如果你希望增加某个快捷能力（例如规则检查、专用报告模板、批处理流程），建议在 Skill 管理页先沉淀为可复用 Skill，再进入常规分析流程。
