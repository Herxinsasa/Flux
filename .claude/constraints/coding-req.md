# 通用编码约束

**分级**：【必须】违反必须修复；【应当】违反须列出理由，理由成立可不改；【建议】仅参考。
**优先级**（从高到低）：

1. **项目既有风格**：应用项目已有较强且统一的编码风格（既有代码、项目文档）时，与项目保持一致；仅当项目做法本身存在格式或约束错误时，以本约束为准纠正。
2. **语言生态惯例**：Python 蛇形命名、Go 错误返回值、Java 文件名与类型名一致等。
3. **本约束**。

## 一、文件与目录

- 【必须】文件命名风格全项目统一：C/C++/Python/Go 用小写 + 下划线（`data_sync_worker.cpp`），Java/C# 用与类型名一致的 PascalCase；禁止多风格混用。
  - 反例：同项目内 `LightClient.cpp` 与 `data_sync_mgr.cpp` 并存。
- 【必须】UTF-8（无 BOM）；全仓库统一 LF 行尾，由 `.gitattributes` 保证；文件末尾保留换行。
- 【应当】目录按功能模块划分并保持扁平；
- 【必须】无内容不建空目录，生成物不入库。

## 二、命名

- 【必须】名称表意，禁止数字编号（`value1`、`data2`）。
- 【必须】互斥概念用反义词组（`add/remove`、`open/close`）；同一概念全项目同名。
- 【必须】布尔量命名可按真假解读：`isReady`、`hasError`。
- 【应当】全局函数名为动宾词组（`loadConfig`）；类成员函数可用纯动词，宾语即对象自身。生态无强惯例时以下表为基线：

| 对象 | 风格 | 示例 |
|------|------|------|
| 类型（类 / 接口 / 枚举） | PascalCase | `DataSyncWorker` |
| 函数 / 方法 | camelCase | `getOperationLogFile()` |
| 变量 / 参数 | camelCase | `errorCode` |
| 常量 | `k` + PascalCase 或全大写下划线，全项目二选一 | `kMaxBufferSize` |
| 模块 / 包 / 命名空间 | 小写 | `data_sync` |

## 三、注释

- 【必须】优先使用 Doxygen 风格标签（`@brief` / `@param` / `@return`），以各语言标准文档载体承载（C/C++ `/** */`、Python docstring、JS/TS JSDoc、Java JavaDoc、Go doc）；公共接口注明用途、参数、返回值与可能的错误：
  ```
  // @brief  获取运维日志文件
  // @param   type  运维文件类型
  // @param   file  输出运维文件数据
  // @return  是否成功
  getOperationLogFile(type, file)
  ```
- 【必须】TODO 格式 `TODO(username): 说明`（如 `TODO(dev): 补充错误码转换逻辑`），禁止匿名 TODO；注释掉的死代码、占位注释不得提交。
- 【必须】注释与代码同步，失效注释立即删除；
- 【建议】代码自明时不加注释。

## 四、表达式与语句

- 【必须】无复杂多用途复合表达式，一行内不允许多个副作用；
- 【应当】运算符多的表达式用括号明确优先级。
- 【必须】类型转换显式进行，不依赖隐式收窄。
- 【必须】布尔量不与字面量比较；空值比较用语言标准写法，不与 `0` 比较：
  - 正例：`if (isReady)`、`if (ptr == nullptr)`、`if (value is None)`
  - 反例：`if (isReady == true)`、`if (ptr == 0)`
- 【应当】浮点数用误差范围比较，不直接用 `==`。
- 【必须】循环体内不修改循环变量；分支出口必须显式，故意 fallthrough 要注释说明（优先用 `[[fallthrough]]` 等语言属性）。
- 【应当】提前返回降低嵌套，分支嵌套 ≤ 4 层。

## 五、函数

- 【应当】函数体 ≤ 50 行（不含空行与注释）、参数 ≤ 5 个；超出则拆分或封装参数对象。
- 【必须】函数名与返回值语义一致（`getName` 不返回数值，`isXxx` 返回布尔）；获取语义的函数不得有副作用。
- 【必须】公共接口在入口校验参数；断言仅用于内部不变式，不替代外部输入的运行时校验。

## 六、类型与数据

- 【必须】变量与成员在声明处显式初始化，不依赖隐式默认值：
  ```
  struct Config {
      timeoutMs = 5000      // 默认 5 秒超时
      enableRetry = true    // 默认启用重试
  }
  ```
- 【必须】重复出现的数字与字符串提取为命名常量，禁止魔法值（反例：`if (retry > 3)`；正例：`if (retry > kMaxRetry)`）。
- 【必须】下标、区间、偏移运算检查边界，防止多一/少一。
- 【应当】不修改的数据用不可变类型（`const` / `final` / `readonly`）；语言提供固定宽度类型时优先于平台相关宽度类型。

## 七、面向对象设计（OO 代码适用）

- 【应当】遵循六大原则：单一职责（如 `LocalStorageMgr` 只管本地存储，不承担网络通信）、开闭、里氏替换、接口隔离、依赖倒置、最少知识。
- 【必须】继承必须满足 "is-a"；不相关类之间用组合复用，禁止为复用而继承。

## 八、错误处理、资源与安全

- 【必须】错误显式处理或显式传播，禁止静默吞错（空 catch、忽略错误返回值）；错误信息包含对象、操作、原因。
  - 正例：`failed to open camera 1, reason: timeout`；反例：`failed`。日志侧要求见《日志规范约束》（`../log-requirement/log-req.md`）。
- 【应当】全项目统一一种错误策略（错误码 / 异常 / Result）并贯彻；非预期状态快速失败。
- 【必须】资源释放使用确定性机制，不靠手动释放或 GC 兜底；锁以作用域守卫释放，持锁范围最小化。
  - 正例：C++ `std::lock_guard<std::mutex> lock(m_mutex)`；Python `with open(path) as f`；Go `defer f.Close()`。
- 【必须】禁止硬编码密码、密钥、token；外部输入使用前必须校验。

## 九、格式化

- 【必须】格式化由 formatter 统一强制（clang-format / gofmt / black / prettier），不靠人工对齐；大括号风格（Allman / K&R）全项目统一，单行语句块也加大括号（反例：`if (isReady) process();`）。
- 【应当】无配置时基线：4 空格缩进（禁 Tab）、行宽 ≤ 120。
- 【建议】import 分组排序由工具托管（isort / goimports），及时移除无用依赖。

## 十、其他

- 【必须】不使用语言社区已废弃的控制结构（如 `goto`）。
- 【应当】开启最严格警告级别，零警告交付；优先用标准库与成熟库，不重复造轮子。

## 十一、语言/框架扩展

语言专属规则（C++ 头文件管理与宏规范、Qt 控件与信号槽命名等）由项目级扩展文档承载，扩展文档须声明细化或覆盖了本约束的哪些条款。
