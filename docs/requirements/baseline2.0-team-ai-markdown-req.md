## 1. 需求概述

| 项 | 内容 |
|---|---|
| 产品定位 | 面向部门和公司团队的轻量 AI Markdown 与常规文本阅读编辑器 |
| 宗旨 | 轻量、高效、流畅；普通用户无需理解 Markdown 工具链或 AI 对话范式即可使用 |
| 核心价值 | 提供接近 Typora 的阅读编辑体验、低于 Obsidian 的学习成本，以及面向团队评审的批注和 AI 审阅能力 |
| 范围 | MD/TXT/LOG 等文本文件的阅读编辑、批注评审、低门槛 AI、性能与轻量发布形态 |
| 非目标 | 实时多人协同、云端账号系统、Obsidian 式知识图谱、替代 IDE、通用文件查看器 |
| 非本次范围 | Word/PDF/Office 预览或编辑、打印/PDF 输出、双链、远程同步、插件市场、复杂日志平台、移动端、macOS/Linux 首发适配 |
| 需求项数量 | 16 |
| 是否涉及 UI | 是 |

### 1.1 Structured-thinking 剪枝结论

| 思维框架 | 结论 |
|---|---|
| 问题重定义 | 团队缺少的是打开即用、适合本地文本文件的阅读编辑与评审工具，不是另一个 Office 查看器 |
| 第一性原理 | 最小闭环是“打开文本 → 舒适阅读/编辑 → 人工或 AI 评审 → 保存/导出文本结果” |
| 奥卡姆剃刀 | 复用现有 Electron、CodeMirror、MDXEditor、Agent 和大日志索引；删除 Office/PDF、专业打印及其他高兼容成本能力 |

**MVP 必须有**

- MD/TXT/LOG 的快速打开、稳定编辑或大文件阅读。
- Markdown 舒适阅读和可靠 WYSIWYG。
- 不污染原文的人工批注闭环；AI 自动评审在 P1 基于同一批注模型扩展。
- 选区 AI 快捷操作；完整对话面板仅按需出现。
- 启动、目录加载和大文件处理过程保持流畅。

**本次明确不做**

- Word、PDF 或其他 Office 文件的内置预览和编辑。
- 打印排版、PDF 导出和 Office 格式转换。
- 为每种文本扩展名建设独立富媒体查看器。

## 2. 需求项

### REQ-001：轻量默认工作区与功能剪枝

| 项 | 内容 |
|---|---|
| 级别 | 大 |
| 交付优先级 | P0 |
| 目标 | 让 Flux 默认表现为阅读编辑器，而不是以 AI 聊天为中心的工具 |
| 触发条件 | 用户正常启动应用或打开文档 |
| 正常路径 | 默认显示文件区域和编辑器；AI 对话按需呼出并恢复当前会话；用户选择的布局状态可持久化 |
| UI 影响 | 是 |
| 初步影响范围 | 布局、状态管理、启动流程、设置、快捷键 |
| 非目标 | baseline2.0 不删除 Provider、Skill 和日志索引等底层能力，但不让高级入口占据默认工作区 |

**验收标准**

- 用户可一键进入或退出极简模式。
- 极简模式仅保留文档工作所需区域，不出现无效空白。
- 重启应用后恢复上次布局选择。
- AI 面板隐藏时不阻塞编辑器启动和文件加载。
- 呼出或关闭 AI 面板时不丢失当前会话和文件上下文。

**异常场景**

- AI 请求执行中隐藏面板时，请求状态不得丢失或导致应用无响应。

**待确认**

- 无。

### REQ-002：快速启动、最近文件与首次引导

| 项 | 内容 |
|---|---|
| 级别 | 中 |
| 交付优先级 | P0 |
| 目标 | 消除空白首页和首次使用门槛 |
| 触发条件 | 用户未通过文件关联直接打开文件时启动应用 |
| 正常路径 | 应用先呈现可交互窗口，再异步初始化非必要能力；显示最近 10 个文件或工作区；首次启动显示不超过 3 张引导卡片 |
| UI 影响 | 是 |
| 初步影响范围 | 启动流程、首页、持久化、文件服务 |
| 非目标 | 不建设营销型首页和复杂新手教程 |

**验收标准**

- 冷启动期间不得长时间白屏或阻塞操作；文件扫描、Skill 和 Provider 等非首屏能力延迟初始化。
- 最近列表最多显示 10 项，失效路径有明确状态且可移除。
- 首次引导内容精简、可跳过，完成后默认不重复展示。

**异常场景**

- 最近文件不存在、无权限或位于离线位置时，不阻塞首页加载。

**待确认**

### REQ-004：WYSIWYG 与 Markdown 阅读体验

| 项 | 内容 |
|---|---|
| 级别 | 大 |
| 交付优先级 | P0 |
| 目标 | 提供可长期阅读和编写部门文档的稳定体验 |
| 触发条件 | 用户打开或编辑 Markdown 文件 |
| 正常路径 | 用户在源码、阅读预览和 WYSIWYG 模式间切换，内容和光标语义保持一致 |
| UI 影响 | 是 |
| 初步影响范围 | MDXEditor、Markdown 渲染、主题、编辑器路由、保存链路 |
| 非目标 | 不追求完全复刻 Typora 的所有扩展语法 |

**验收标准**

- H1-H6、正文、引用、列表、任务列表、代码块、表格、链接和图片层级清晰。
- 亮色和暗色主题下文字、代码块、表格均满足可读性要求。
- 三种模式切换不丢内容、不重复写入、不破坏 Markdown 源文。
- 长文滚动、目录跳转和输入过程无明显卡顿或布局跳动。

**异常场景**

- 遇到不支持语法时保留原始 Markdown，不静默删除内容。

**待确认**

### REQ-005：批注侧车数据模型

| 项 | 内容 |
|---|---|
| 级别 | 大 |
| 交付优先级 | P0 |
| 目标 | 在不污染原文的前提下保存可版本管理的评审意见 |
| 触发条件 | 用户对文档选区添加、修改或删除批注 |
| 正常路径 | 批注写入同目录下 `<原文件名>.review.json`，记录定位信息、正文、状态和必要元数据 |
| UI 影响 | 否 |
| 初步影响范围 | 数据模型、文件服务、保存、外部修改检测、Git 工作流 |
| 非目标 | 不实现服务端多人实时批注同步 |

**语义关系**

| 项 | 内容 |
|---|---|
| 关系 | 独立 |
| 参考对象 | Markdown 原文件 |
| 一致行为 | 跟随原文件路径和文件生命周期 |
| 差异行为 | 批注独立存储，不修改原文件正文 |

**验收标准**

- 没有批注时不创建空侧车文件。
- 添加批注后侧车文件为 UTF-8、结构稳定、可读且适合 Git diff。
- 重新打开文档可恢复批注及其状态。
- 原文变化导致定位失效时明确标记“需重新定位”，不得绑定到错误文本。

**异常场景**

- 只读目录、侧车 JSON 损坏、外部并发修改时给出可恢复提示，不破坏原文件。

**待确认**

- 无。

### REQ-006：批注交互与批注模式

| 项 | 内容 |
|---|---|
| 级别 | 大 |
| 交付优先级 | P0 |
| 目标 | 形成低学习成本的文档评审体验 |
| 触发条件 | 用户选中文字后右键添加批注，或打开已有批注文档 |
| 正常路径 | 正文显示非侵入高亮；侧栏显示批注列表；正文和侧栏可互相定位 |
| UI 影响 | 是 |
| 初步影响范围 | 编辑器选区、上下文菜单、装饰层、侧栏、状态管理 |
| 非目标 | 不实现多人在线光标和实时评论推送 |

**验收标准**

- 用户可添加、编辑、删除、完成和重新打开批注。
- 普通阅读模式不显示批注装饰，批注模式不改变原文排版宽度和内容。
- 点击批注可定位正文，点击正文高亮可定位批注。
- 重叠批注、跨段批注和已失效批注具有可辨识状态。

**异常场景**

- 原文选区为空时不允许创建无锚点批注。

**待确认**

- 无。

### REQ-007：带批注导出

| 项 | 内容 |
|---|---|
| 级别 | 中 |
| 交付优先级 | P1 |
| 目标 | 让评审结果可以脱离 Flux 分发给钉钉、飞书或邮件用户 |
| 触发条件 | 用户在含批注的文档中选择导出 |
| 正常路径 | 用户选择 Markdown 或 HTML，系统生成正文清晰、批注可追溯的文件 |
| UI 影响 | 是 |
| 初步影响范围 | 导出服务、批注模型、Markdown/HTML 渲染 |
| 非目标 | 不直接调用钉钉或飞书开放接口发送文件 |

**验收标准**

- HTML 导出在常用浏览器中可独立阅读，不依赖 Flux 运行环境。
- 导出结果包含批注内容及其对应原文，不暴露本地绝对路径。
- 用户取消导出或写入失败时不产生残缺文件。
- 默认 Markdown 导出使用正文中的醒目编号标记、脚注详情和文末评审清单，兼顾定位与汇总。
- 用户可选择“展开评审”模式，在对应段落后插入引用块；默认模式不同时展开引用块，避免同一批注重复三次造成阅读噪音。
- HTML 导出使用正文高亮、编号和可定位的批注区域，视觉表现应比纯 Markdown 更明显。

**待确认**

- 无。

### REQ-008：AI 自动评审

| 项 | 内容 |
|---|---|
| 级别 | 大 |
| 交付优先级 | P1 |
| 目标 | 将 AI 结果落入可处理、可追踪的批注流程 |
| 触发条件 | 用户右键或通过命令执行“AI 审阅此文” |
| 正常路径 | AI 检查逻辑漏洞、格式问题、表述歧义和错别字；结果先预览，再由用户确认写入批注侧车文件 |
| UI 影响 | 是 |
| 初步影响范围 | Agent、上下文预算、Prompt、批注模型、流式状态、错误处理 |
| 非目标 | AI 不自动修改原文，不将模型结论视为最终事实 |

**验收标准**

- 每条 AI 评审意见包含问题类型、原文定位、说明和建议。
- 用户可逐条接受、忽略或转为普通批注。
- AI 请求失败、取消或超时不产生半成品批注。
- 大文档超出上下文时明确说明覆盖范围。

**待确认**

- 无。

### REQ-009：选区 AI 快捷操作

| 项 | 内容 |
|---|---|
| 级别 | 中 |
| 交付优先级 | P0 |
| 目标 | 让非技术用户无需打开聊天面板即可使用高频 AI 能力 |
| 触发条件 | 用户选中文本后右键或使用浮动工具条 |
| 正常路径 | 提供总结、翻译、改写、解释、扩写、缩写、语法修正、正式化和口语化等预设动作 |
| UI 影响 | 是 |
| 初步影响范围 | 编辑器选区、上下文菜单、浮动工具条、Agent、diff 预览 |
| 非目标 | 不在首版提供无限制 Prompt 编排器 |

**验收标准**

- 右键菜单至少提供 AI 总结、AI 翻译、AI 改写。
- 浮动工具条不遮挡选区和关键正文，键盘用户可访问相同能力。
- 常用 Prompt 以普通用户可理解的动作名称呈现，不要求用户编写 Prompt。
- 改写类结果必须预览差异并由用户确认应用，支持撤销。
- 无 Provider 时给出直接、可操作的配置入口。

**异常场景**

- 选区过长时提示范围限制，不静默截断后直接改写原文。

**待确认**

- 无。

### REQ-011：MD/TXT/LOG 常规文本支持

| 项 | 内容 |
|---|---|
| 级别 | 大 |
| 交付优先级 | P0 |
| 目标 | 为团队最常见的 Markdown、纯文本和日志文件提供一致、可靠的工作体验 |
| 触发条件 | 用户打开 `.md`、`.txt`、`.log` 或可识别的纯文本文件 |
| 正常路径 | MD 使用 Markdown 模式；TXT 使用纯文本模式；LOG 根据大小进入编辑模式或索引阅读模式；其他文本格式回退到纯文本模式 |
| UI 影响 | 是 |
| 初步影响范围 | 文件路由、编码检测、编辑器模式、LogViewer、保存链路 |
| 非目标 | 不预览或编辑 Word/PDF/Office 文件，不为每种文本扩展名单独建设查看器 |

**验收标准**

- MD、TXT、LOG 可通过文件对话框、文件树、拖拽和系统文件关联打开。
- TXT 打开、编辑、保存不破坏原编码；无法无损保存时先提示用户。
- 大 LOG 不全量载入富文本编辑器，保留索引、等级统计和分段读取能力。
- JSON、YAML、配置文件或源代码等可识别文本可使用通用纯文本/语法高亮模式，不扩张为独立产品能力。
- Word、PDF 或二进制文件不进入内部预览器，并给出清晰的不支持提示。

**待确认**

- 无。

### REQ-016：自动备份与恢复

| 项 | 内容 |
|---|---|
| 级别 | 大 |
| 交付优先级 | P2 |
| 目标 | 在不自动改写原文件的前提下，降低崩溃、误操作和长时间编辑造成的数据丢失风险 |
| 触发条件 | 文档产生未保存修改并达到自动备份条件 |
| 正常路径 | 系统将编辑快照写入 Flux 专用临时缓存目录；只有用户主动保存时才写原文件；异常退出后可从快照恢复 |
| UI 影响 | 是 |
| 初步影响范围 | 编辑器状态、文件写入、冲突检测、恢复、清理策略 |
| 非目标 | 不替代 Git 或企业文档版本管理系统 |

**验收标准**

- 自动备份不得写入或覆盖原文件；用户主动保存时仍需执行外部修改冲突检测。
- 异常退出后可识别并恢复比原文件新的备份。
- 备份写入失败时提示用户，原文件保持可用。
- 安装版缓存目录为 `%LOCALAPPDATA%\Flux\backup-cache`；Portable 版使用 `<Flux目录>\data\backup-cache`，不得依赖 `Program Files` 写权限。
- 文档处于未保存状态时默认每 60 秒生成一次快照；相同内容不重复写入。
- 每个源文件默认最多保留 20 个快照，同时设置默认 500 MB 全局上限；达到任一上限后按最旧优先循环覆盖，数量和容量可配置。
- 恢复快照必须先预览或另存，不得未经确认覆盖磁盘上的原文件。

### REQ-018：AI 对话上下文分层与最小 Harness 化

| 项 | 内容 |
|---|---|
| 级别 | 大 |
| 交付优先级 | P1 |
| 目标 | 让 AI 对话在长文档和连续编辑场景下可预测、可解释、可恢复，并将其作为文档型 Agent Harness 的实践模块 |
| 触发条件 | 用户连续对话、引用文档或选区、调用工具，或输入上下文接近模型限制 |
| 正常路径 | 系统按“固定规则与能力 → 当前任务与文档 → 固定事实 → 冷历史摘要 → 热历史”组织上下文；达到阈值时先压缩冷历史，保留最近对话和固定事实，并明确提示省略范围 |
| UI 影响 | 是 |
| 初步影响范围 | ChatPanel、会话状态、上下文组装、Provider 预算、摘要持久化、日志与测试 |
| 非目标 | 不建设通用多 Agent 平台、自治规划循环、向量数据库或跨团队知识库 |

**当前基线**

- 已有工作摘要、固定结论、最近 16 条热历史、当前文件/选区和 Skill/System Prompt 等基础层次。
- 超过 20 条消息或约 126,000 字符时自动压缩；请求组装仍会将历史限制为最近 24 条、约 140,000 字符，并在必要时删除最早消息。
- 当前工作摘要采用规则抽取，只提取首个用户问题、AI 回复标题/加粗内容/行号/错误关键词，最多 3,000 字符，不是语义摘要。
- 压缩游标当前只记录、不参与增量压缩判断；达到消息阈值后可能在后续每次发送时重复压缩同一段冷历史，旧摘要也可能重复累积后被硬截断。

**最小可用优化**

- 定义唯一的上下文分层数据模型和优先级，Renderer 与 Main 使用同一份预算结果，避免预估与实际请求不一致。
- 将压缩摘要改为结构化格式，至少保留任务目标、已确认事实、用户约束、文档引用、未决问题和下一步；摘要失败时保留原热历史并允许重试。
- 使用压缩游标只处理新增冷历史，避免重复摘要；摘要滚动合并应去重并保留字段级优先级。
- 自动压缩必须原子化：摘要生成并持久化成功后再切换热历史；不得仅依赖静默删除旧消息维持可用。
- 使用 Provider/模型对应的 token 预算；字符估算仅作为无 tokenizer 时的回退策略。
- 通过按需详情展示已保留、已摘要、已截断和未注入的内容，并支持查看摘要及新建干净会话；默认界面不常驻技术明细。
- 保留最近 16 条用户/AI 消息和固定事实；优先裁剪 reasoning、工具原始输出和重复文档内容，再处理普通对话。
- 为自动压缩阈值、摘要滚动合并、持久化失败、模型切换、大文档引用和超限阻止发送建立测试与可观测日志。

**主动压缩命令**

- 对话输入框支持 `/compact`，允许用户在达到自动阈值前主动压缩当前会话；该命令由本地命令路由处理，不作为普通用户消息发送给模型。
- 支持可选关注点，例如 `/compact 保留已确认修改、批注意见和未决问题`；关注点只影响本次结构化摘要，不修改长期固定事实。
- 压缩成功后保留固定规则、固定事实、结构化工作摘要和最近热历史；原始会话记录仍可用于恢复，但不继续占用模型上下文。
- AI 正在生成、写入文件或已有压缩任务执行时不得并发压缩；无可压缩冷历史时仅返回“当前无需压缩”。
- 压缩失败或被取消时继续使用压缩前上下文，不覆盖最后一份有效摘要，也不触发旧消息删除。

**上下文持久化文件管理**

- 私有会话记录、压缩检查点和工作摘要默认存放在 Electron `userData` 下的 `sessions/<workspaceHash>/<sessionId>/`，不得默认写入文档目录或参与 Git 提交。
- 每个会话使用独立、稳定的 `sessionId`；工作区仅作为索引维度，禁止多个会话共用并覆盖同一个 `session-summary.md`。
- 会话原始事件采用可追加的 JSONL；当前状态和压缩检查点采用带 `schemaVersion`、时间、压缩游标、模型信息及文档版本引用的结构化 JSON。
- 检查点采用临时文件写入后原子替换，至少保留当前和上一份有效检查点；启动时遇到损坏文件应回退，不得加载半写入摘要。
- 默认保留最近 30 天会话并设置 200 MB 全局上限，先清理过期且最近未使用的会话；保留周期和容量可在设置中调整，也可立即清空全部 AI 会话数据。
- 固定事实与会话摘要分离：固定事实可跨本工作区会话加载，普通工作摘要只属于当前会话；用户删除会话时应明确两者是否一并删除。
- 从旧版升级时，一次性读取 `.flux/session-summary.md` 并导入为当前工作区的迁移会话；导入成功前不删除旧文件，导入结果可由用户查看和清理。

**交互约束**

- `/compact` 通过输入框现有 Slash 补全入口展示，名称为“压缩上下文”，不新增常驻工具栏按钮。
- 执行期间只在输入区域附近显示单行状态；成功后显示一条可自动消失的简短结果，不使用模态框、连续 Toast、教学卡片或重复警告。
- 默认只展示“已压缩”及保留范围；压缩前后字符/token 估算、文件路径和调试信息放入可选详情或日志，不占据日常对话界面。

**验收标准**

- 连续 30 轮文档编辑对话后，AI 仍能复述已确认目标、用户约束和未决事项，且不会把旧文档内容误当成当前版本。
- 用户可从按需详情查看本轮包含的文件、选区、固定事实和历史层次，以及哪些内容被摘要或截断；默认对话界面不重复展示这些信息。
- 自动压缩或持久化失败不丢失当前 UI 会话，不产生空摘要覆盖有效摘要。
- 输入 `/compact` 可在自动阈值前完成主动压缩；带关注点时，生成的摘要明确保留该关注范围。
- 重启应用后可恢复最近会话及最后有效检查点；两个并行会话不得互相覆盖摘要或压缩游标。
- 默认工作区不新增 AI 私有会话文件；用户可查看存储占用、清理历史，并可关闭会话持久化。
- 切换不同上下文窗口的 Provider/模型时，发送前预算和主进程最终预算一致，不因固定字符阈值误判。
- 新建会话清除工作摘要和热历史；固定事实是否保留有明确提示和可控入口。

**后续增强候选**

- 按相关性选择工作区文档片段、会话命名/分支/搜索、压缩版本撤销、上下文质量评测。
- 用户主动启用的共享工作区上下文；如后续实现，仅写入经过确认的长期事实，不保存完整聊天、工具原始输出、密钥或未经确认的文档正文。

**待确认**

- 无。
