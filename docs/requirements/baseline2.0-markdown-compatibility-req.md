# baseline2.0 Markdown 兼容性与流畅性需求

## 状态

- 需求状态：已确认
- 输入来源：P0/P1 Markdown 渲染清单与流畅性验收
- 产品边界：MD/TXT/LOG 文本阅读编辑器，不扩展 Office 能力

## 目标

1. Markdown 语法准确性不低于 VS Code 内置预览，以 CommonMark + GFM 为基础。
2. 高频编辑体验向 Typora 靠拢，编辑、源码与预览往返不破坏语义。
3. 支持 `[TOC]` 目录、标题跳转、Frontmatter、Mermaid、任务列表、表格、脚注和本地图片。
4. 文件加载、切换、输入、滚动与缩放保持稳定，不出现空白、位置跳变或无故脏状态。

## P0 验收

- `~文本~` 保持普通文本，只有 `~~文本~~` 为删除线。
- 软换行、硬换行、段落、引用、列表、任务列表、标题、代码、链接、图片、表格、脚注、转义和安全 HTML 符合 CommonMark/GFM 语义。
- 标题锚点支持中文、重复标题和编辑/预览跳转。
- 打开文档不改变正文，不产生无故“已编辑”状态。
- 源码、编辑和预览往返后语义稳定。

## P1 验收

- 独占一行的 `[TOC]` 在预览和编辑界面显示标题目录，实时反映 H1-H6，点击可跳转。
- 插入菜单可插入 `[TOC]`，源码界面保留字面量。
- Frontmatter、Mermaid、代码语言高亮、图片附件和批注不破坏 Markdown 原文。
- 外部修改可重新加载，编辑状态和提示行为保持现有契约。

## 流畅性验收

- 连续快速切换 Markdown 文件 20 次不出现空白。
- 常规文档进入编辑面有明确反馈；富文本上限外自动使用源码模式。
- 10KB、500KB、1MB 文档可加载、输入和滚动；5MB 以上走源码/采样保护。
- 75%-250% 缩放保持内容居中；图片和 Mermaid 随内容缩放，不因宽度约束反向缩小。
- 编辑器初始化失败时回退源码界面，不留下不可操作空白页。

## 非本次范围

- 数学公式、Callout、Emoji 短代码、上下标、高亮扩展。
- Office、音视频和不受控复杂 HTML。
