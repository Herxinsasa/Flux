# baseline2.2 Code Review

## 第一轮独立审查

| 级别 | 发现 | 处理结果 |
| --- | --- | --- |
| P0 | AI 跨文件应用结果未等待文件切换，可能覆盖当前草稿 | 已修复：等待未保存确认和目标切换，随后强制从磁盘水合；取消时不写当前 editor store |
| P1 | 关闭仅检查当前标签，遗漏后台脏 session | 已修复：按最近使用顺序遍历全部 dirty session |
| P1 | 2 MB 后只显示采样，不符合长文本目标 | 已修复：完整加载上限提升到 16 MB；超富文本预算的 MD 默认源码模式 |
| P1 | 新文件异步加载时继续显示旧正文 | 已修复：先创建空白只读 loading session，再读取新文件 |
| P1 | 富文本批注按可见文本次数匹配会被链接 URL 干扰 | 已修复：通过 ProseMirror 临时边界标记和 Milkdown serializer 映射 Markdown 偏移 |
| P2 | 源码每键向 Zustand 复制完整字符串 | 已修复：CodeMirror 内部增量维护，160 ms 合并写入；保存、批注、切换和丢弃前 flush/clear |
| P2 | 非 Markdown 页面可留下待执行命令 | 已修复：顶部命令禁用，非 Markdown adapter 主动清除残留 |
| P2 | 格式标题和 Setext 标题无法可靠大纲跳转 | 已修复：大纲文本归一化并支持 Setext；同名标题保留 occurrence |

## 剩余人工风险

- Electron 窗口关闭握手需要人工覆盖保存、不保存、取消和多个脏标签。
- 8-16 MB Markdown/TXT 的连续输入与滚动需要在目标办公电脑上体感验证。
- 富文本跨多个 marks、链接和重复文本的批注位置需要人工检查高亮与侧车锚点。
- 当前没有 AI 绘画设置，未新增相关入口。

## 第二轮复审

第二轮发现 AI 确认应用、AI 后台目标事件和清空工作区仍可能绕过 dirty 保护。已分别在写盘、强制重载和清除 session 前接入目标文件确认及全部 dirty session 遍历。修复后再次独立复审，结论为三项均关闭，无剩余 P0/P1。
