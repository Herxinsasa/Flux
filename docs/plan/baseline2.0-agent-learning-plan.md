# Flux baseline2.0 文档 Agent 学习开发计划

## 定位与边界

在 Flux 现有 AI 对话、文档上下文、Skill、批注和修改预览能力之上，逐步构建可学习、可验证的文档 Agent。

- 服务范围：当前工作区内的 Markdown、TXT 和日志文本。
- 默认权限：只读；写文件必须先生成修改预览，再由用户确认。
- 产品边界：Flux 仍是轻量 Markdown 阅读、编辑与评审工具，不建设通用自动化平台或多 Agent 编排系统。
- 会话原则：普通聊天随退出清理；仅为未完成 Agent 任务保存最小恢复摘要与操作记录。

## 分块迭代路线

### 阶段 0：现状地图

- 目标：梳理现有 AI 对话、Skill、文件读取、批注注入与修改预览的完整链路。
- 学习主题：Agent 的基础组成：模型、上下文、工具、执行策略。
- 产物：当前能力与缺口图；已有工具的输入、输出和写入权限清单。
- 验收：可明确说明当前 AI 能读到什么、不能读到什么、哪些动作会修改文件。

### 阶段 1：文档只读工具集

- 目标：统一工作区内的读取、搜索、列出文件、读取批注等工具协议。
- 学习主题：Tool Schema、输入校验、工作区权限边界、上下文选择。
- 产物：结构化只读工具及引用来源展示。
- 验收：Agent 能完成“审阅当前需求并指出遗漏”，并能展示结论对应的文档依据。

### 阶段 2：任务卡与过程记录

- 目标：让每次 Agent 任务都具备目标、读取文件、调用工具、结果和失败原因。
- 学习主题：Agent Loop、任务状态机、可观测性。
- 产物：对话内可展开的任务过程记录。
- 验收：用户可查看 Agent 做过哪些操作，以及每次操作的原因和结果。

### 阶段 3：修改提案与确认写入

- 目标：Agent 将修改意图转化为结构化计划和 diff 预览，确认后才写入文件。
- 学习主题：人在回路、文件事务、失败回滚、变更审计。
- 产物：修改计划、差异预览、确认写入和结果记录。
- 验收：可完成“根据批注修改文档”，并支持预览、确认、写回和失败说明。

### 阶段 4：Skill 调度

- 目标：保留 `/skill` 显式调用，并增加 Agent 的 Skill 推荐能力；推荐不等于自动执行。
- 学习主题：Planner 与 Executor 分离、Skill 注册与路由。
- 产物：推荐 Skill、推荐原因和用户确认入口。
- 验收：Agent 能说明为何推荐某个 Skill，并在确认后正确调用。

### 阶段 5：轻量任务恢复

- 目标：仅保存未完成任务的摘要和工具操作记录，支持恢复进行中的工作。
- 学习主题：Agent Memory、Checkpoint、上下文压缩。
- 产物：任务恢复卡和最小持久化结构。
- 验收：重启后可恢复“上次正在处理什么”，普通闲聊不会长期堆积。

### 阶段 6：评估与打磨

- 目标：建立固定的真实文档任务集，持续验证 Agent 行为。
- 学习主题：Agent Eval、提示词迭代、失败归因。
- 产物：覆盖读取、评审、批注、修改的任务集和结果记录。
- 验收：每次 Agent 改动均可回归验证成功率、错误工具调用和耗时。

## 推荐实施顺序

`阶段 0 → 阶段 1 → 阶段 2 → 阶段 3 → 阶段 4 → 阶段 5 → 阶段 6`

先让 Agent 可靠地理解和引用文档，再展示执行过程；确认读写链路可信后，再扩展 Skill 推荐和任务恢复。

## 首个最小场景

读取当前 Markdown 与关联批注，生成一份带引用依据的评审结论，不修改任何文件。

## 明确暂不做

- 多 Agent 协作与编排。
- 无确认的自动写文件。
- 跨工作区的广泛文件访问。
- 为普通闲聊长期保存完整历史。
